# Release Notes for v0.24.0

Release Date: November 21st, 2026

This release is based on [4.4.0](https://github.com/kata-containers/kata-containers/releases/tag/4.4.0) of Kata Containers.
This Kata release adopts the Rust shim as the default for many runtime classes.
Confidential Containers still uses the Go shim for now, but will transition in the future.

This release uses v0.23.0 of Trustee and v0.23.1 of guest components.
Trustee and the guest components use KBS protocol v0.4.0.

Trustee and guest components use Rust v1.95.0 with MSRV 1.94.1.

Please see the [quickstart guide](https://confidentialcontainers.org/docs/getting-started/) or [project documentation](https://confidentialcontainers.org/docs/) for more information.

## What's New

* This is the first release with Trustee following its own release process prior to the Kata and CoCo releases.
* Trustee can integrate with an existing SPIRE Agent and server to deliver confidential SPIFFE SVIDs as a delegated agent.
* HTTP return codes for the KBS have been improved.
* ARM CCA is supported in the default attestation policy.
* Trustee uses EAR v4 token format.
* Improvements for RVPS and Trustee storage more generally including better support for TTL.
* Rust edition 2024
* MSRV tracking for Trustee and Guest Components
* Improvements to TDX verifier
* NVIDIA verifier can now use NVIDIA Attestation SDK Local and Remote modes.
* Improvements to EventLog support 
* Attestation Policy has EventLog helper extension.
* Admin interface supports HTTP1 and HTTP2 requests.
* KBS Client adds generic set-reference-value command that supports all RVPS extractors.
* KBS can be built reproducibly in some configurations.
* Secret CLI helper included in release.
* Guest components use system-wide OpenSSL as crypto backend.
* Guest component binaries reduced in size.
* Various improvements to Guest Components extension image
* Some dependencies have been trimmed or replaced for ease of vendoring.

## Hardware Support

Attestation is supported and tested on three platforms: Intel TDX, AMD SEV-SNP, and IBM SEL.
Not all features have been tested on every platform, but those based on attestation
are expected to work on the platforms above.

Make sure your host platform is compatible with the hypervisor and guest kernel
provisioned by CoCo.

## Limitations

The following are limitations and known issues with this release.

* On Azure TDX and SNP platforms, rapid consecutive attestation requests can fallback
  to the sample attester.
* Credentials for authenticated registries are exposed to the host.
* LUKS-based secure storage provides integrity protection, but not replay protection.
* Not all features are tested on all platforms.
* Guest pull with nydus snapshotter sometimes fails.
* Guest pull may have negative performance implications.
* `crio` support is still evolving.
* Containerd versions older than v2.3.x may have issues with guest pull.
* SELinux is not supported on the host and must be set to permissive if in use.
* A secure Kata agent policy must be used to protect the guest, but this may not support some Kubernetes commands, such as exec.
