# Release Notes for v0.23.0

Release Date: September 24th, 2026

This release is based on [4.2.0](https://github.com/kata-containers/kata-containers/releases/tag/4.2.0) of Kata Containers.
This Kata release adopts the Rust shim as the default for many runtime classes.
Confidential Containers still uses the Go shim for now, but will transition in the future.

This release uses v0.22.0 of Trustee and guest components.
Trustee and the guest components use KBS protocol v0.4.0.

Trustee and guest components use Rust v1.95.0.

Please see the [quickstart guide](https://confidentialcontainers.org/docs/getting-started/) or [project documentation](https://confidentialcontainers.org/docs/) for more information.

## What's New

* Experimental PQC support for Trustee attestation
* Provisioner plugin added to Trustee
* guest-components provides Kata extension image
* Improved support for pre-provisioning SNP VCEKs
* Trustee Helm chart can use Redis/Valkey for storing session information.
* Minor changes to TCB Claims generated by Trustee
* Improved support for HTTPS in Trustee Helm chart
* RVPS supports listing reference values
* RVPS supports deleting reference values 
* Attestation service supports selectable attestation policy
* Trustee allow-all KBS Policy allows resources from all plugins
* Trustee external plugin enabled by default
* KBS resource plugin supports listing resources.
* Minor improvements to KBS Client
* Optimizations for TDX verification
* Improvements to eventlog handling in guest-components
* Improvements to image unpacking in image-rs
* Improvements to logging for image-rs
* Image-rs supports optional fallback to anonymous registry auth
* Guest-components provides NVIDIA attester with all x86 builds
* Secret CLI tool published as a package
* Secret CLI tool supports generating keys
* Improvements to ASR
* eHSM and online-sev-kbc support removed from guest-components
* SNP attester uses configfs-tsm

## Hardware Support

Attestation is supported and tested on three platforms: Intel TDX, AMD SEV-SNP, and IBM SEL.
Not all features have been tested on every platform, but those based on attestation
are expected to work on the platforms above.

Make sure your host platform is compatible with the hypervisor and guest kernel
provisioned by CoCo.

## Limitations

The following are limitations and known issues with this release.

* Credentials for authenticated registries are exposed to the host.
* LUKS-based secure storage provides integrity protection, but not replay protection.
* Not all features are tested on all platforms.
* Guest pull with nydus snapshotter sometimes fails.
* Guest pull may have negative performance implications.
* `crio` support is still evolving.
* Containerd versions older than v2.3.x may have issues with guest pull.
* SELinux is not supported on the host and must be set to permissive if in use.
* A secure Kata agent policy must be used to protect the guest, but this may not support some Kubernetes commands, such as exec.
